## 3. Decisions Made

| Decision | Rationale |
|----------|-----------|
| Relax `agentyper` from `==0.1.12` to `>=0.1.12` | Latest release is the same version; pin was needlessly strict. |
| Migrate to `SecurityQuery` rather than pinning `pydantic-market-data` back to 0.2.x | Both `py-ftmarkets` 0.4.0 and `py-yfinance` 0.1.15 already use `SecurityQuery`; staying on 0.2.x would block those upgrades. |
| Model `price_on` as `None` when only one of price/date is supplied | `PriceOnDate` requires both fields; partial data cannot form a valid verification point. |
| FIGI lookup in `find_candidates` deduplicates against existing candidates | Avoids double-returning the same instrument when ISIN and FIGI both match. |

---

## 4. Decisions Refused / Alternatives Rejected

| Rejected Approach | Reason |
|-------------------|--------|
| Keep `pydantic-market-data` at `>=0.2.0` | Would have left the codebase on an outdated API with known renaming; providers 0.4.0/0.1.15 already depend on the new name. |
| Expose a `SecurityCriteria` alias in `registry.py` for backward compat | No external consumers rely on the re-export; adding an alias would be dead code. |
